# Kit v1.1: short 3D engineering explainers (Claude + Higgsfield)

This kit is the code used by the skills `3d-engineering-video`, `reference-short-teardown` and `higgsfield-blender-render` (the `skills/` folder of this repo). The skills describe the workflow; the kit holds the tools. The kit grew out of video #1 (septic system, English) and video #2 (swimming pool, Indonesian). Version 1.1 adds the lessons from video #3 (CR-V engine, Indonesian), the first production that used the kit and the skills together. All three are in `examples/`.

## Install

```bash
git clone --depth 1 https://github.com/davidalfasunarna/3d-engineering-video-claude-skills ~/3dv-repo
cp -r ~/3dv-repo/kit ~/kit
pip install --break-system-packages bpy==5.3.0 pillow numpy    # Blender as a Python module; needs Python 3.13, about 1 GB
bash ~/kit/selftest.sh                                          # 3 to 10 minutes on CPU, no credits; must end with SELFTEST PASSED
```

What the working machine needs:

| Requirement | Used for | Notes |
|---|---|---|
| Python 3.13 with `bpy==5.3.0`, `pillow`, `numpy` | scene, previews, captions | on the GPU box, `box/setup.sh` installs them |
| ffmpeg and ffprobe | encoding, QA | |
| The Inter font (`fonts-inter`) | text inside the scene, `phrases` captions, contact sheets | without Inter, scene text falls back to Blender's built-in font (the digit "1" looks like "I") |
| `Baloo2.ttf` (OFL license) | `cards` captions | `newjob.sh` downloads it from the Google Fonts repo; it is not included here |
| tesseract with `pytesseract`, `scipy` | `ref_teardown.py captions` | only for analysing a reference video |
| faster-whisper | `audio/asr.py` | already present in the Higgsfield sandbox |

The kit has been tested in Claude's cloud workspace (Linux, 2 CPU cores), in the Higgsfield sandbox, and on a rented Higgsfield GPU box (L40S). It has not been tested anywhere else.

## Contents

| File | Purpose |
|---|---|
| `explainer_kit.py` | the scene core: time from words (`T`), keyframes, basic shapes, text, materials, camera, render modes. Generated by `make_kit.py` from the video #1 script; unchanged since video #2 (md5 `f66672403b57`) |
| `scene_extras.py` | additions from video #2: shapes with a pivot, arrows, pulses, pop-in, water (level, body, material), flow dots in pipes, screen projection, the mascot, trees |
| `scene_template.py` + `demo/` | the smallest complete scene (a rooftop water tank) with sample data, a two-sentence Indonesian narration; the starting point for a new scene script |
| `kitjob.py`, `job.env.example` | one source of numbers for one video: name, language, caption style, FPS, lead-in, tail; `DUR` and the frame count are derived from `words.json` |
| `scene_check.py` | checks a scene without rendering: camera steps, when each screen-fixed object is visible, and one-or-two-frame flashes with their peak second. `python3 scene_check.py <scene>.py` |
| `captions.py` | captions and encoding: style `cards` (one or two words, key words in yellow) and style `phrases` (a phrase that fills in word by word); reads PNG frames or a clean master |
| `audio/` | `audition.py` (measure audition clips), `vo_prep.py` (tighten pauses, tempo, loudness), `asr.py` + `align.py` (word timings, giving `words.json`); language `id` or `en` |
| `box/` | `job.sh`, `setup.sh`, `vo_final.sh`, `render.sh`, `rerender.sh`, `finish.sh`, `after.sh`, `up.sh`, `scan.py`, `trip_png.py`, `compare.py`, `diffall.py`, `sheets.py`, `qa_final.py` |
| `sandbox/` | `final_check.sh`, `sync_check.py`, `scan_video.py`, `trip.py` (QA of the finished file, free) |
| `ref_teardown.py` | measures a reference video: `probe`, `sheets`, `captions`, `pace`, `motion`, `audio` |
| `newjob.sh` | creates a flat job folder from the kit |
| `selftest.sh` | a small end-to-end test on CPU, no credits |
| `make_api.py`, `make_kit.py` | generate `API.md` and `explainer_kit.py` |
| `make_bundle.py` | packs the small kit files into one Markdown document (`kit_tools.md`) and unpacks it again; useful if you want to keep the kit as a document in a claude.ai Project |
| `GUIDE.md` | the working guide for the skills: writing a scene, previews, voice per language, reading the scan, pitfalls, reference numbers |
| `API.md` | the scene functions with their arguments (regenerate with `python3 make_api.py > API.md`) |

## One video is one job folder

`bash newjob.sh <folder>` copies the kit code into one flat folder. The workspace, the sandbox and the GPU box all work in a folder like that. The files that belong to the job:

| File | Where it comes from |
|---|---|
| `job.env` | filled in at the start: `NAME`, `SCENE`, `LANG_CODE`, `CAPTION_STYLE`, `TAIL` |
| `script.txt` | the script, one line per sentence-picture: `S01\|text`. Numbers are written as words. Phrase breaks for the `phrases` style: ` / ` |
| `keywords.txt` | the yellow key words for the `cards` style: `S01 word [nth]` |
| `vo_raw.mp3`, then `vo_proc.wav` | the voice from Higgsfield, processed by `vo_prep.py` |
| `words.json` | `asr.py` + `align.py` in the sandbox |
| `<scene>.py` | the scene script, started from `scene_template.py` |
| `urls.sh` | presigned upload URLs, written near the end of the render and deleted by `after.sh` after use (on the box only; single-use; never keep them in a repo or a document) |

Try an example job without spending credits:

```bash
cp -r ~/3dv-repo/examples/video02-swimming-pool-id ~/jobs/pool && bash ~/kit/newjob.sh ~/jobs/pool && cd ~/jobs/pool
python3 pool_video.py still 270 480 4 st 3.6 27.2 47.6          # three small stills, a few seconds each
python3 captions.py test st/t_02720.png 27.2 st/c_02720.png     # caption on top of a still
```

## Known limits

- 1080x1920 at 30 fps only.
- The v1.0 `box/` scripts rendered video #3 on a rented GPU box (L40S) from start to upload, including two partial re-renders. The v1.1 changes to `after.sh` and `rerender.sh` have been tested on CPU only.
- The new scene functions from video #3 (`bake`, `land`, `hud_label`, `dial`, `frame`, `tag`, `carve`) still live in that video's scene script and are not in `scene_extras.py` yet.
- `selftest.sh` takes 3 to 10 minutes in Claude's workspace (three processes share two cores). If a render process is killed for memory, `selftest.sh` v1.1 resumes the remaining frames with one process.
- Claude cannot judge sound, motion or feel. That stays a human job.

## Releasing a change to the kit

1. Change the files, then run `bash selftest.sh` until it prints `SELFTEST PASSED`.
2. Bump `VERSION` and add a line under "History". If `explainer_kit.py` changed, update its md5 in the "Contents" table.
3. Run `python3 make_api.py > API.md` if scene functions changed.
4. Commit to the repo. The skills take the kit from the main branch, so the change is used by the next session.
